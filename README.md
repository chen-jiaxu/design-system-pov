# Design System POV

ブラウザだけで使えるデザインシステムのツールです。

- コンポーネントを書いて props を試せます
- キャンバスでページを組み立てられます
- Design Token のパターンを定義して比較できます

解析・コンパイル・プレビューはすべてブラウザの中で動き、サーバーは不要です。ビルド結果は静的ファイルなので、GitHub Pages に置くだけで使えます。

公開先：<https://chen-jiaxu.github.io/design-system-pov/>

## できること

- インストール不要、ブラウザで開けばすぐ使える
- コンポーネントの props は型から読み取る（stories を書かなくてよい）
- キャンバスにコンポーネントをドラッグして並べ、ページを組み立てる
- Design Token（色・サイズ・フォントなど）のパターンを並べて比較する
  - 使用中のパターンがグローバルな CSS 変数になる
  - 決まったパターンはエクスポートできる
- 書いたコードを zip にまとめてダウンロードする

## 画面

上のバーで「コンポーネント」と「Design Token」を切り替えます。どちらも同じレイアウトです。

| 場所 | 内容                                                                 |
| ---- | -------------------------------------------------------------------- |
| 左   | アウトライン                                                         |
| 中央 | ビューポート                                                         |
| 右   | プロパティパネル                                                     |
| 下   | コードパネル。最初は閉じていて、タイトルバー右の「</> コード」で開く |

### コンポーネント

- アウトラインでコンポーネントを選ぶと、プレビューが表示される
- タイトルバーで「1 つ」と「バリエーション一覧」を切り替えられる
  - バリエーション一覧：選択肢・スイッチの props ごとに 1 行ずつ、その prop だけ値を変えて並べる
  - ほかの props はプロパティパネルの値を使う
- プロパティパネルの機能：
  - props の変更
  - 使っている Token の確認
  - 外側に包む Provider の選択
- コードパネルのタブ：ソース、使い方、変更
- コードパネルにカーソルがあるときに ⌘S / Ctrl+S を押すと、プレビューに反映される
  - 構文エラーがあるときは反映せず、エラーの行番号を表示する
- 「+」でコンポーネントやページを新規作成できる

### キャンバス（ページ）

- アウトラインのコンポーネントを、キャンバスまたは右の構造ツリーにドラッグして置く
  - コンポーネントの間に落とすと、その前後に並ぶ
  - `children` を持つコンポーネントの真ん中に落とすと、その中に入る
- キャンバス上での操作：
  - ドラッグで位置を入れ替える
  - クリックで選択し、プロパティパネルで props を変更する
  - Delete キーで削除する
- 構造ツリーでも、ドラッグ・上下移動・削除ができる
- アウトラインのページの「サンプル」から、一覧・フォーム・ダッシュボードのページを追加できる
  - サンプルで使うコンポーネントのうち、ワークスペースにないものも一緒に追加する（既にあるファイルは変えない）
- ページの保存先：
  - 構造：`src/pages/名前.canvas.json`
  - 生成されたコード：`src/pages/名前.tsx`

### Design Token

- 複数のパターンをタイトルバーのタブで切り替える
  - 選んだタブのパターンが使われ、タブに「使用中」と表示される
- 使用中のパターンは `src/tokens.css` に書き出される
  - コンポーネントのプレビューとキャンバスにすぐ反映される
  - コンポーネントのスタイルや生成されたページから `var(--変数名)` で使える
- 中央はドキュメントのような表で、名前と説明を書ける
- 「並べて比較」に切り替えると、同じコンポーネントやページをパターンごとに並べて表示する
- 種類は 8 つ：色、サイズ、フォント、ウェイト、時間、シャドウ、数値、その他
- 値の入力方法は種類ごとに違う。どの種類でも、ほかの Token を `var(--xxx)` で参照できる

  | 種類         | 入力方法       |
  | ------------ | -------------- |
  | 色           | カラーピッカー |
  | サイズ・時間 | 数値と単位     |
  | ウェイト     | プルダウン     |

- 色について自動で計算するもの：
  - OKLCH
  - 白背景とのコントラスト比（文字色に使えるか）
  - 「比較するパターン」を選んだときの ΔE
- 変数名の変更：
  - 入力欄からフォーカスが外れたときに反映される
  - 次の 3 か所も一緒に書き換わる：全パターンの同名 Token、その Token を参照している値、コンポーネントのスタイル内の `var(--旧名)`
- 影響範囲：選んだ Token を変えると影響するものを、プロパティパネルに表示する
  - その Token を参照している Token（参照の参照もたどる）
  - それらを使っているコンポーネントとページ。名前を押すと開く
- 削除するとき：その Token をまだ使っているコンポーネントと Token が一覧で表示される
- パターンのステータス：下書き・レビュー中・承認済み
  - 変えた日付が残る
  - タブと「並べて比較」に表示し、共有リンク・Markdown・JSON にも入る
  - 「パターンをコピー」で作ったパターンは下書きから始まる
- 「表から貼り付け」でドキュメントからコピーした表を取り込める
  - 各行に `#RRGGBB`、`8px`、`150ms` のような値が必要
- エクスポート：
  - コードパネルで CSS、JSON（Design Tokens 形式）、Markdown を表示・コピー・ダウンロードできる
  - 「共有リンクをコピー」はパターンをリンクに埋め込む。開いた人が確認すると、その人のワークスペースに追加される
  - 同じ名前のパターンがすでにあるときは、名前の後ろに「（共有）」を付ける
- `src/tokens.css` はパターンから生成されるファイル。コードパネルでは閲覧のみ

### 編集操作

- 元に戻す・やり直し：
  - ⌘Z / Ctrl+Z で元に戻す
  - ⇧⌘Z / Ctrl+Y でやり直し
  - タイトルバーの ↶ ↷ も使える
  - キャンバスと Design Token のパターンは、それぞれ別に履歴を持つ
  - 入力欄の中では、入力欄自身の元に戻すが働く
- 確認・入力は、ブラウザのポップアップではなくアプリ内のダイアログで行う
- 画面の幅が 900px 未満のとき：左右のパネルは閉じ、上のバーの ☰（アウトライン）と ⚙（プロパティ）で開く
- 表示言語：
  - 選んでいない間はブラウザの言語に合わせる（日本語・中国語。それ以外は英語）
  - 上のバーの右端で切り替えられる

## ワークスペースと保存

- 保存先はブラウザの IndexedDB。ワークスペースは複数持てる
  - 上のバー右のメニューで操作する：切り替え、新規作成、zip から読み込み、名前の変更、削除
- 新規作成したときの中身は、内蔵のサンプル（`templates/starter`）
  - コンポーネント 10 個と、サンプルページ 3 つ（一覧・フォーム・ダッシュボード）
  - 画面に出る文言は日本語
- 次のものはワークスペースと一緒に保存され、再読み込みしても消えない：
  - 変更したファイル
  - 新しく作ったコンポーネントとページ
  - Design Token のパターン
- ステータスバーの「zip をエクスポート」：
  - ワークスペースの全ファイルと `design-tokens.json`（全パターン）をまとめる
  - 「zip から読み込み」で、別のブラウザでも続きができる
- 保存に失敗したとき：
  - 画面の上に原因と「もう一度試す」が表示される
- 同じワークスペースが別のタブで変更・削除されたとき：
  - このタブでは保存しない（別のタブの内容を上書きしない）
  - 再読み込みするよう案内が出る
- ブラウザを変えたり、ブラウザのデータを消したりすると、内容はなくなる
  - 持ち出すときは zip でエクスポートする

## 解析とプレビュー

- 解析は Web Worker の中で TypeScript が行う。読み取るもの：コンポーネント、props、Token
- 最初に開いたときは約 1.5 MB（圧縮後）をダウンロードする
  - 時間がかかっているときは画面に案内が出る
  - 読み込みに失敗したときは再試行できる
- コンポーネントは Worker で CommonJS にコンパイルされ、iframe 内のプレビューページで実行される
  - エラーが出ても画面は落ちず、原因を表示する
  - 直すと自動で元に戻る
- プレビューページはサンドボックス（`sandbox="allow-scripts"`）の中で動く
  - 画面側のデータは読めない
  - ブラウザがサンドボックス内のページをブロックするとき（一部の拡張機能など）は、サンドボックスなしに自動で切り替わる
- プレビューから長く応答がないとき（コンポーネント内の無限ループなど）は、プレビューを再読み込みできる
- import できるのは `react`、`react-dom` とワークスペース内のファイルだけ
- スタイルは CSS だけに対応。SCSS・Less は「まだ使えません」と表示する

## 解析で読み取れるもの

| 対象                                      | ルール                                                                                                                                                                      |
| ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| コンポーネント                            | `src/components` の下の `.tsx` を読む。大文字で始まり JSX を返す export をコンポーネントとみなす（アロー関数、`function` 宣言、default export に対応）。hook と定数は対象外 |
| Provider                                  | 名前が `Provider` で終わるものはコンポーネントとは別に Provider として並べる。プレビューで選ぶと、コンポーネントの外側に包む                                                |
| props                                     | TypeScript の型から、コンポーネント自身が定義した props を読む。JSDoc と分割代入のデフォルト値も読む。props の種類は下の表のとおり                                          |
| 継承した HTML 属性                        | 数だけ数える。`children` と `disabled` は例外で、自身の props と同じように並べる                                                                                            |
| サンプル値                                | JSDoc の `@example` に書いた値を、プレビューやキャンバスに置いたときの初期値にする。ないときは、必須のテキストに prop 名を入れる                                            |
| 定義された Token                          | ワークスペースの CSS / SCSS / Less で、`:root` と Tailwind v4 の `@theme` に書かれた CSS 変数                                                                               |
| コンポーネントが使う Token                | CSS 変数の書き方なら、コンポーネントが import する CSS / SCSS / Less の `var()`（コンポーネント内部だけの変数は除く）                                                       |
| コンポーネントが使う Token（Tailwind v4） | クラス名を `@theme` の変数に置き換えて調べる（`bg-primary` → `--color-primary`）。`hover:` などの variant と透明度にも対応                                                  |
| パスエイリアス                            | ワークスペース直下の `tsconfig.json` を読む（`@/` など）。`lib` は ES2022 と DOM で固定                                                                                     |
| まだ表示できないもの                      | 非同期コンポーネント（Server Component）は印を付け、理由を書く                                                                                                              |

props として扱う種類：

| 種類     | 例・扱い                                                      |
| -------- | ------------------------------------------------------------- |
| 選択肢   | 文字列リテラルの union 型                                     |
| スイッチ | boolean                                                       |
| テキスト | string                                                        |
| 数値     | number                                                        |
| スロット | ReactNode など                                                |
| 関数     | イベントハンドラなど                                          |
| データ   | オブジェクト・配列など。型からサンプルを作り、JSON で編集する |

解析の単体テストのデータ：

- 基本は `templates/starter` を読む
- サンプルページのコード（`src/pages/名前.tsx`）は構造（`.canvas.json`）から生成したもの。テストで一致を確かめる
  - 構造やコンポーネントを変えたら `UPDATE_TEMPLATE=1 npx vitest run src/workspace/template.test.ts` で作り直す
- 次の書き方はテストの中に書いたデータを使う：SCSS、Less、Tailwind、Provider、非同期コンポーネント

## 開発（このツール自体を変更するとき）

Node 22.12 以上（`.nvmrc` を参照）と npm が必要です。

| コマンド            | 内容                                                                                   |
| ------------------- | -------------------------------------------------------------------------------------- |
| `npm install`       | 依存関係のインストール（初回のみ）                                                     |
| `npm run dev`       | 開発サーバーを起動（`http://localhost:5181`）。ソースを変えるとすぐ反映される          |
| `npm run build`     | 型チェックのあと `dist/` にビルド（画面の `index.html` とプレビューの `preview.html`） |
| `npm run typecheck` | 型チェック                                                                             |
| `npm test`          | テスト（Vitest）                                                                       |
| `npm run lint`      | Biome で lint とフォーマットをチェック                                                 |
| `npm run format`    | Biome でフォーマットを直し、import を並べ替える                                        |

設定はルートの `.env` にあります。コマンド実行時に同じ名前の環境変数を指定すると、そちらが優先されます。

| 変数            | 内容                                                                        | 既定値              |
| --------------- | --------------------------------------------------------------------------- | ------------------- |
| `VITE_APP_NAME` | プロダクト名。ページのタイトル、上のバー、エクスポートした zip の説明に出る | `Design System POV` |
| `VITE_BASE`     | 公開するパス。GitHub Pages のプロジェクトページでは `/リポジトリ名/`        | `/`                 |

git hook（husky）：

- commit 前：staged のファイルを Biome でチェック
- push 前：`npm run typecheck` と `npm test` を実行

## デプロイ（GitHub Pages）

`.github/workflows/deploy.yml` が次の手順を自動で行います：

- テスト
- ビルド
- GitHub Pages への公開

実行されるタイミング：

- `main` に push したとき
- Actions 画面から手動で実行したとき

最初の 1 回だけ、次の設定が必要です。

1. リポジトリの Settings → Pages → Build and deployment → Source を **GitHub Actions** にする
2. `main` に push する（または Actions → Deploy to GitHub Pages → Run workflow）
3. 完了すると `https://chen-jiaxu.github.io/design-system-pov/` で開ける

補足：

- 公開パスは自動で `/リポジトリ名/` になる。リポジトリ名を変えても追従する
- 次の値は、Settings → Secrets and variables → Actions → Variables で変数を作ると上書きできる：

  | 変数            | 使う場面                   | 例                  |
  | --------------- | -------------------------- | ------------------- |
  | `VITE_BASE`     | 独自ドメインを使うとき     | `/`                 |
  | `VITE_APP_NAME` | プロダクト名を変えたいとき | `Design System POV` |

- GitHub Pages は誰でも見られる（Enterprise のプライベート Pages を除く）
  - ワークスペースの中身は各自のブラウザにだけ保存され、アップロードされない
  - 社内の色などのデータはリポジトリに入れない
- 同じアカウントの GitHub Pages のプロジェクトページ（`アカウント.github.io/リポジトリ名`）は、オリジンを共有する
  - ほかのプロジェクトページからも、ここの IndexedDB を読み書きできる
  - 分けたいときは、独自ドメインを使うか、別のアカウント・Organization に置く

## ディレクトリ構成

| 場所                 | 内容                                                                                                                                                                                                   |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `src/ui/`            | 画面。詳しくは下の表を参照                                                                                                                                                                             |
| `src/workspace/`     | Worker 本体（`worker.ts`）、プレビューで動くモジュールへのコンパイル（`compile.ts`）、テンプレートの読み込み（`template.ts`）                                                                          |
| `src/analyzer/`      | 解析：コンポーネントの検出、型からの props の読み取り、Token の読み取り。メモリ上のファイルだけを読み、Node に依存しない。`type-libs.node.ts` はビルドとテストのときに `node_modules` から型定義を読む |
| `src/preview/`       | プレビューページ（`preview.html`）：モジュールの読み込み（`modules.ts`）、コンポーネントとキャンバスの描画、キャンバス上のクリック選択とドラッグ＆ドロップ（`canvas.ts`）、エラーの受け止め            |
| `src/shared/`        | 共通部分：コンポーネント一覧の形式、色の計算（コントラスト比、OKLCH、ΔE）、zip の作成と読み込み、プロダクト名                                                                                          |
| `templates/starter/` | 新しいワークスペースの初期内容。解析の単体テストのデータも兼ねる                                                                                                                                       |

`src/ui/` の中身：

| ファイル                                                           | 役割                                                                          |
| ------------------------------------------------------------------ | ----------------------------------------------------------------------------- |
| `workspace.ts`                                                     | ワークスペース（テンプレート＋下書き）。解析とコンパイルは Worker に任せる    |
| `session.ts`、`storage.ts`                                         | ワークスペースを IndexedDB に保存する（バージョンの確認、ほかのタブへの通知） |
| `drafts.ts`                                                        | コードパネルのファイル。同じファイルへの操作は順番に処理する                  |
| `Canvas.tsx`、`canvas-tree.ts`、`page-code.ts`、`pages.ts`         | キャンバス                                                                    |
| `TokenMode.tsx`、`design-tokens.ts`、`apply-tokens.ts`、`share.ts` | Design Token                                                                  |
| `token-impact.ts`                                                  | Token の影響範囲（参照している Token、コンポーネント、ページ）                |
| `dialog.tsx`                                                       | 確認と入力のダイアログ                                                        |
| `export.ts`                                                        | zip のエクスポートと読み込み                                                  |

画面の見た目は `--bl-*` 変数で決めていて、コンポーネント側の Token とは分けています。

その他のルール：

- テストはテスト対象のファイルの隣に置き、`*.test.ts(x)` という名前にする
- 型チェックの設定：
  - ブラウザで動くコード：`tsconfig.json`（Node の型なし）
  - テスト、`*.node.ts`、`vite.config.ts`：`tsconfig.node.json`
- TypeScript と型定義は、ビルド後にそれぞれ約 3.5 MB（非圧縮）になる。Worker が最初に解析するときだけ読み込む
